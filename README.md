# the-lobby

Run `task` to list the commands. The screens (the public welcome, The VIP Lobby, Privacy, Let's Plan Soccer at `/soccer`, the Minecraft Launcher at `/minecraft` and Foundry at `/foundry`) are a React app in [web/](web/), built by `task ui:build` into `internal/web/dist`, where the Go server embeds them; `task run` builds them first. Building them needs Node 20.19 or later; `task ui:test` needs Node 22.18 or later.

The Let's Plan Soccer screen is here; its league access and calendar files are the [soccer](https://github.com/CraigDevJohnson/soccer) backend's (ADR 0001). The site forwards `/api/soccer/*` and the public Session link address `/soccer/link/{token}.ics` to the address in `SOCCER_BACKEND_URL`, signing each request outside a developer's computer (ADR 0006). `SOCCER_BACKEND_SIGNING` overrides that when set: `lambda` signs even locally, to try the deployed backend from a developer's computer with AWS credentials and a region, and `off` never signs. With `task run` it defaults to `http://127.0.0.1:8081`, where the soccer repo's own `task run` listens. When the backend cannot be reached the page says so; nothing is simulated. A Member with the `soccer` grant also gets My calendar: Remembered teams under `/api/soccer/me`, kept in the site's own table, and a secret Member link at `/soccer/link/member/{secret}.ics` that the site builds through the backend's `POST /feeds` (ADR 0011). With sign-in disabled on a developer's computer, My calendar answers `401 signed_out`. The same Members also get Add to Google Calendar (ADR 0007): the site connects their Google account at `/soccer/google/connect` and `/soccer/google/callback`, keeps that access encrypted in its table, and on each press of Add writes the games the backend's `POST /events` builds into the calendar they pick (`/api/soccer/google`, `/api/soccer/google/add`, `/api/soccer/google/disconnect`). It reads the Google client's ID and secret and the token key from the SecureStrings `client-id`, `client-secret` and `token-key` under the Parameter Store path in `GOOGLE_PARAMETERS` (`/the-lobby/<env>/google/` when deployed); unset, the page doesn't offer it. `infra/google/wizard.sh`, run on Craig's Mac, walks through the Google Cloud side for dev and production and saves those settings. The code is public under the MIT licence; it is not taking contributions.

The Minecraft Launcher's page and access check are here; the server's status and Start server belong to the [minecraft](https://github.com/CraigDevJohnson/minecraft) repo's launcher backend. [docs/minecraft-backend.md](docs/minecraft-backend.md) is the contract the site calls at `MINECRAFT_BACKEND_URL` (signed like the soccer backend, overridden by `MINECRAFT_BACKEND_SIGNING`). Until it is set, the page says no server is set up for the Launcher.

Foundry's access check is here. The player page at `/foundry` is the-lobby #24, and since #29 it also offers starting and stopping; Foundry Admin's page is not built yet; the Foundry server's status, and starting and stopping it, belong to the [foundry](https://github.com/CraigDevJohnson/foundry) repo's controller. [docs/foundry-backend.md](docs/foundry-backend.md) is the contract the site calls at `FOUNDRY_BACKEND_URL` (signed like the soccer backend, overridden by `FOUNDRY_BACKEND_SIGNING`) for `/api/foundry/server`, `/api/foundry/server/start` and `/api/foundry/server/stop`, which each need the `foundry` or `foundry-admin` grant; a stop also needs the Member's confirmation that nobody is playing. Until it is set, a Member with either grant is told Foundry has no server configured. `FOUNDRY_JOIN_URL`, Foundry's join page, is given to a Member with either grant when the status can't be checked. The foundry repo's `task run` serves the controller locally for `curl`; the site's route can't reach it there, because sign-in is disabled on a developer's computer and it answers `401 signed_out`.

The family devices page at `/admin` serves the two configuration profiles for the family's devices, rendered by `internal/profile` from `KIDS_DOH_URL`, `ADULTS_DOH_URL` and `GATEWAY_ROOT_CA_PEM`, the outputs of `infra/zero-trust` (ADR 0009). It sits behind its own Cloudflare Access application for the two adults and never looks at the Sign-in session (ADR 0010). `site profile kids|adult` writes the same files on a computer. Until the settings are set, the page says the profiles are not configured yet.
